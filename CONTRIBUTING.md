# Участие в проекте

Можно помочь кодом, скиллом, описанием ошибки или идеей по удобству работы.
Готовое исправление не обязательно.

## Сообщить об ошибке или предложить улучшение

Создайте [Issue](https://github.com/cloud-ru/mlspace-plugin/issues) и укажите:

- что вы хотели сделать;
- что ожидали и что получилось;
- версию плагина, ОС и клиент;
- короткие шаги воспроизведения.

Для ошибок настройки можно приложить [диагностический журнал](REFERENCE.md#диагностические-логи).
Не прикладывайте ключи, `.env`, персональные данные или дамп окружения.
Об уязвимости сообщите приватно: [aogabbasov@cloud.ru](mailto:aogabbasov@cloud.ru).

## Предложить свой скилл

Скилл — инструкция агенту для повторяющейся задачи: например, подготовить обучение
или найти причину неудачного переноса. **Пользовательские скиллы приветствуются.**

1. Опишите задачу, условия применения и способ проверить результат.
2. Создайте `skills/mlspace-<сценарий>/SKILL.md`; возьмите соседний файл как пример.
3. Используйте существующие инструменты MCP и вымышленные данные в примерах.
4. Проверьте скилл и приложите пример запроса пользователя.

```sh
uv run --locked pytest tests/test_skills.py
```

Сохраняйте предусмотренные сервером подтверждения операций. Не включайте реальные
ключи, личные воркспейсы и конфигурацию организации. В описании отдельно укажите,
что проверено по исходникам, что — локально, а что — на реальном API.
Если писать скилл пока неудобно, начните с Issue с описанием ручного сценария.

## Подготовить окружение разработчика

Нужны Git, uv и Python 3.10+. Из корня репозитория:

```sh
uv sync --locked --extra dev
```

Основные проверки:

```sh
uv run --locked pytest
uv run --locked ruff check src scripts tests
uv run --locked mypy src
uv run --locked python scripts/gen_plugin.py --check
```

API-тесты используют вымышленные ключи и HTTP-моки. TLS-тесты поднимают локальный
HTTPS-сервер; для них нужен доступ к loopback-сокетам. Проверки настоящих клиентов
работают во временных домашних каталогах и пропускаются, если клиента нет.
Не подставляйте настоящие ключи и не меняйте свои клиентские конфиги ради тестов.

## Где искать код

Вызов проходит путь: **агент → MCP-инструмент → клиент MLSpace → API**.

| Файл или каталог в `src/mlspace_mcp/` | Назначение |
| --- | --- |
| `init_cli.py`, `client_setup.py`, `native_plugins.py` | Настройка доступа и подключение клиентов |
| `server.py`, `__main__.py` | Запуск сервера, регистрация инструментов и CLI |
| `tools/` | Операции отдельных сервисов |
| `registry.py` | Общая проверка и выполнение операций, режимы чтения и dry-run |
| `client.py`, `auth.py` | HTTP-запросы, авторизация и обновление токена |
| `config.py` | Настройки и выбор файла ключей |
| `workspace_context.py`, `resource_refs.py` | Воркспейсы и адреса ресурсов |
| `overview.py` | Обзор ресурсов и полнота результатов |
| `job_hooks.py` | Проверки перед операциями с задачами |
| `formatting.py`, `errors.py` | Формат ответов, маскирование секретов и ошибки |
| `bodyspec.py`, `spec/` | OpenAPI и схемы тел запросов |

Скиллы находятся в `skills/`. Состав поставки описан в [PLUGIN.md](PLUGIN.md).
Для ручного запуска с ключами явно задайте `MLSPACE_ENV_FILE`: `.env` из текущего
каталога автоматически не читается. Секреты не должны попадать в коммиты и сообщения об ошибках.

## Обновить схемы или манифесты

После изменения версии пакета выполните:

```sh
uv run python scripts/gen_plugin.py
```

Для обновления API замените соответствующую часть `src/mlspace_mcp/spec/openapi.json`
и запишите источник, дату и область изменения в `x-mlspace-snapshot-updates`.
Не меняйте общую версию API при обновлении только части схемы.
Затем пересоберите схемы тел и запустите проверки:

```sh
uv run python scripts/gen_body_schemas.py
uv run --locked pytest
```

Примеры должны содержать `example.com` и явные placeholders.
Аннотации `example`/`examples` не переносятся генератором в runtime-схемы.
Контрактные тесты выявляют операции, исчезнувшие из встроенной схемы или помеченные deprecated.

## Отправить изменение

Создайте ветку и [Pull Request](https://github.com/cloud-ru/mlspace-plugin/pulls).
В одном изменении решайте одну задачу. Опишите новое поведение и выполненные проверки.
Для исправления добавьте проверку наблюдаемого поведения, если она нужна для защиты от повторения ошибки.

Порядок выпуска для сопровождающих — в [RELEASE.md](RELEASE.md).
