# Установка и первое подключение

Эта инструкция — для macOS и Linux. На Linux по SSH выполняйте команды на той машине,
где работает ваш Claude Code, Codex или OpenCode. Браузер для настройки не нужен.

Обычный путь: **проверить инструменты → запустить настройку → открыть клиент**.

## 1. Подготовьте инструменты и ключи

Установите хотя бы один клиент: Claude Code, Codex или OpenCode.
Понадобятся также [Git](https://git-scm.com/install/) и [uv](https://docs.astral.sh/uv/getting-started/installation/).
`uv` скачивает и запускает плагин; подходящий Python 3.10+ он может установить сам.

Проверьте, что команды доступны в терминале:

```sh
git --version
uv --version
uvx --version
```

Подготовьте **Cloud.ru Key ID** и **Cloud.ru Key Secret**.
Воркспейсы вы выберете из списка — вручную получать `x-api-key` не требуется.

Если установку делает агент, ключи всё равно вводите вы в своём терминале.
Агенту достаточно сообщить «настройка завершена», без ключей и содержимого файлов.

## 2. Запустите настройку

Скопируйте всю команду:

```sh
uvx --python ">=3.10" \
  --from "git+https://github.com/cloud-ru/mlspace-plugin.git@main" \
  mlspace-plugin setup
```

Первый запуск может занять время: скачиваются исходники и зависимости.
Дальше мастер проведёт вас по шагам:

1. **Клиенты.** Один найденный клиент подключится автоматически. Если их несколько,
   отметьте нужные и нажмите Enter.
2. **Ключи.** Вставьте Key ID, затем Key Secret. Ввод отображается звёздочками.
   Вставляйте только значения, без названий переменных.
3. **Воркспейсы.** Найдите и отметьте один или несколько воркспейсов.
4. **Проверка и подключение.** Мастер проверит доступ, сохранит настройки,
   подключит MCP и скиллы, затем проверит запуск сервера.

### Как выбрать воркспейсы

| Действие | Клавиши |
| --- | --- |
| Найти по названию, проекту или ID | Начните печатать |
| Перейти к строке | ↑ / ↓ |
| Выбрать или снять отметку | Space |
| Очистить строку поиска | Ctrl-U |
| Подтвердить выбор | Enter |
| Отменить настройку | Ctrl-C |

**Ctrl-U очищает только поиск.** Уже отмеченные воркспейсы остаются выбранными.
Чтобы снять отметку, найдите воркспейс и ещё раз нажмите Space.
Для продолжения должен быть выбран хотя бы один воркспейс.

Если нет доступа к одному из выбранных воркспейсов, мастер вернёт вас к выбору.
Проверенные останутся отмечены. Можно выбрать другие или повторить проверку;
вводить ключи заново не нужно.

## 3. Откройте клиент и проверьте подключение

После успешной настройки откройте новую сессию Claude Code, Codex или OpenCode.
Если MCP не появился, полностью перезапустите клиент.

Напишите агенту:

> Покажи выбранные воркспейсы и запущенные задачи, ничего не меняй.

**Ожидаемый результат:** агент показывает выбранные воркспейсы и обращается к MLSpace.
Сервер запускается клиентом автоматически; отдельный терминал для него не нужен.

## Обновление и повторная настройка

Чтобы обновить сервер и скиллы или изменить набор воркспейсов:

```sh
uvx --refresh --python ">=3.10" \
  --from "git+https://github.com/cloud-ru/mlspace-plugin.git@main" \
  mlspace-plugin setup --force
```

На прежнем адресе API мастер использует сохранённые ключи. После завершения
откройте новую сессию клиента. Свои скиллы храните отдельно от кеша нативного плагина:
обновление заменяет его файлы.

Для других задач добавьте к команде выше нужные параметры:

| Что нужно | Что добавить в конец команды |
| --- | --- |
| Заменить ключи | `--replace-credentials` |
| Подключить ещё один клиент | `--client opencode` — либо `claude-code`, либо `codex` |
| Указать другой API, например stage | `--base-url https://mlspace-stage.example.com` — замените пример своим адресом |
| Передать сертификат от администратора | `--ca-file '/путь/к/corporate-ca.pem'` |

Повторная настройка обновляет сохранившиеся подключения, созданные мастером.
Удалённые подключения сами не восстанавливаются. Своего фонового автообновления
у плагина нет; [как обновляются разные клиенты](PLUGIN.md#обновления).

## Если что-то пошло не так

| Ситуация | Что делать |
| --- | --- |
| Ошибка сертификата | Получите доверенный PEM у администратора. [Настройка TLS](REFERENCE.md#сертификаты-и-адрес-api) |
| В OpenCode найден другой конфиг или изменённый скилл | Мастер предложит оставить свою версию или сделать замену с резервной копией. [Разбор конфликтов](REFERENCE.md#конфликты-в-opencode) |
| Ключи сохранены, но клиент не подключён | Устраните указанную причину и выполните команду после «Повторите команду» |
| `blocked by enterprise policy` | Обратитесь к администратору: источник плагина запрещён политикой. Повтор установки это не исправит |
| После установки агент не видит MLSpace | Откройте новую сессию; при необходимости перезапустите клиент |

Если нужна помощь, приложите диагностический `.log`, путь к которому напечатал
мастер. Для ошибки при работе с агентом нужен свежий `server-*.log` из
`~/.config/mlspace-plugin/logs/`. [Подробнее о логах](REFERENCE.md#диагностические-логи).
Файл с ключами `.env` отправлять не нужно.

## Где хранятся ключи

По умолчанию — в `~/.config/mlspace-plugin/.env`, с правами `0600`.
Файл доступен вашему пользователю и администратору системы; это не шифрование.
Ключи остаются вне плагина и не теряются при его обновлении.
[Настройка другого пути](REFERENCE.md#файлы-настроек).

## Другие способы установки

- Плагин уже установлен в Claude Code или Codex: попросите агента **«настрой MLSpace»**.
  Он даст команду только для настройки доступа.
- Есть скачанный репозиторий или ZIP: [локальная установка](REFERENCE.md#установка-из-локальной-копии).
- Нужна установка без вопросов в терминале: [инструкция для агента и автоматизации](INSTALL_AGENT.md).
