## Файлы настроек

Обычную конфигурацию создаёт `setup`; вручную заполнять её не нужно.

| Файл или каталог | Назначение |
| --- | --- |
| `~/.config/mlspace-plugin/.env` | Ключи и выбранные воркспейсы |
| `~/.config/mlspace-plugin/credentials-path.json` | Указатель на используемый файл ключей |
| `logs/` в каталоге настроек | Диагностические журналы |
| `install-state.json` в каталоге настроек | Подключения и скиллы, которыми управляет мастер |
| `backups/setup-*` в каталоге настроек | Резервные копии перед заменой конфликтующих файлов |

Каталог настроек учитывает `XDG_CONFIG_HOME`. Путь к файлу ключей можно задать
через `setup --path '/полный/путь/credentials.env'`. Указатель сохраняется в
стандартном пользовательском каталоге, поэтому клиент найдёт файл и при другом
окружении запуска. Если указатель повреждён или файл пропал, сервер сообщит об ошибке.

Права файла ключей — `0600`, каталога MLSpace — `0700`. Это ограничение доступа,
а не шифрование: процессы того же пользователя и администратор могут прочитать файл.
Не добавляйте его в Git и не передавайте в чат.

Приоритет настроек, от высшего к низшему:

1. Переменные окружения процесса.
2. Файл, явно указанный через `MLSPACE_ENV_FILE`.
3. Файл, сохранённый мастером `setup`.

Файл `.env` из текущего рабочего каталога автоматически не загружается.
`setup` получает `x-api-key` сам и не сохраняет его. Обмен ключей на токен
авторизации также выполняется внутри сервера, без отдельного вызова агента.

## Переменные окружения

Обычно достаточно настроек мастера. Эти параметры нужны для ручной конфигурации.

### Доступ к MLSpace

| Переменная | Значение |
| --- | --- |
| `MLSPACE_CLIENT_ID` | Cloud.ru Key ID; обязателен |
| `MLSPACE_CLIENT_SECRET` | Cloud.ru Key Secret; обязателен |
| `MLSPACE_WORKSPACES` | JSON со списком выбранных воркспейсов: `id`, `name`, `project_name`; записывает мастер |
| `MLSPACE_WORKSPACE_ID` | ID одного воркспейса, если список `MLSPACE_WORKSPACES` не задан |
| `MLSPACE_API_KEY` | Необязательный готовый `x-api-key` для одного воркспейса; обычно получается автоматически |
| `MLSPACE_BASE_URL` | Адрес API; по умолчанию `https://api.ai.cloud.ru` |
| `MLSPACE_ENV_FILE` | Явный путь к файлу настроек |
| `MLSPACE_CA_FILE` | Дополнительный доверенный сертификат PEM |
| `MLSPACE_NAMESPACE` | Явный Kubernetes namespace; по умолчанию определяется для воркспейса |

Список `MLSPACE_WORKSPACES` также допускает необязательный `api_key` у записи.
Мастер его не сохраняет. Для обычной установки не формируйте этот JSON вручную.

### Поведение сервера

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MLSPACE_READONLY` | `false` | Только чтение: блокировать изменения ресурсов |
| `MLSPACE_DRY_RUN` | `false` | Проверять запросы на изменение без их отправки |
| `MLSPACE_ALLOW_REGISTRY_PASSWORD_ROTATION` | `false` | Разрешить операцию смены пароля Registry |
| `MLSPACE_TRANSPORT` | `streamable-http` | Транспорт; установленный плагин явно использует `stdio` |
| `MLSPACE_HOST` / `MLSPACE_PORT` | `127.0.0.1` / `8000` | Адрес и порт локального HTTP-сервера |
| `MLSPACE_ENABLED_DOMAINS` | Все | Сервисы через запятую, которыми ограничен набор инструментов |
| `MLSPACE_TIMEOUT` | `60` | Таймаут API-запроса в секундах |
| `MLSPACE_LIST_DEFAULT_LIMIT` | `50` | Размер списка по умолчанию |
| `MLSPACE_LIST_MAX_LIMIT` | `200` | Максимальный размер списка |
| `MLSPACE_LOG_TAIL_LINES` | `200` | Число последних строк лога задачи в ответе |

## Режимы работы и подтверждения

**По умолчанию доступны чтение и изменение ресурсов.** Чтобы ограничиться чтением,
добавьте в файл настроек, созданный мастером, строку:

```dotenv
MLSPACE_READONLY=true
```

Затем перезапустите клиент. Сервер уберёт действия изменения из описаний инструментов
и будет блокировать их при вызове. Для проверки запросов на изменение без отправки
есть отдельный режим `MLSPACE_DRY_RUN=true`.

Некоторые опасные действия требуют аргумента `confirm=true`.
Его передаёт сам агент — это не окно согласия пользователя. Если нужно подтверждать
операции лично, настройте согласование инструментов в своём клиенте.
Права доступа по-прежнему проверяет API MLSpace. Создание и удаление воркспейсов
через bootstrap/debootstrap в набор инструментов не включены.

### Пароль Registry и раскрытие секретов

Смена пароля Registry выключена отдельно, потому что влияет на аккаунт и его
действующие подключения. Для согласованной смены нужно установить
`MLSPACE_ALLOW_REGISTRY_PASSWORD_ROTATION=true` и перезапустить MCP.
`setup` этого не делает. После операции выключите параметр и снова перезапустите MCP.
Один лишь `confirm=true` не разрешает смену пароля.

Секреты в ответах по умолчанию маскируются. Получение ключа воркспейса
(`mlspace_workspaces`, `get_api_key`) и смена пароля Registry
(`mlspace_docker_registry`, `generate_password`) допускают явное раскрытие:
`reveal_secret=true` вместе с `confirm=true`.

Раскрытый секрет становится доступен модели и может остаться в истории клиента.
Для `docker login` используйте `--password-stdin`; не помещайте пароль в обычный
ответ или репозиторий. `generate_password` именно меняет пароль, а не читает старый.
Если новый пароль нужен для входа, аргумент раскрытия передаётся сразу при смене.
Обычным MCP-запросам ручное получение ключа воркспейса не требуется.

Режим только для чтения блокирует изменения, но не запрещает явное чтение ключа
воркспейса. Настройки MCP не заменяют ограничения API и клиента; агент с доступом
к файлу настроек способен их изменить.

## Сертификаты и адрес API

По умолчанию используется production API: `https://api.ai.cloud.ru`.
Для другого окружения добавьте к команде настройки `--base-url` с его HTTPS-адресом.
При смене адреса мастер запросит ключи заново, если источник ключей явно не указан.

Плагин доверяет системным сертификатам: Keychain на macOS и OpenSSL trust store
на Linux. Если нужного сертификата нет, мастер попросит путь к PEM-файлу
от администратора. Его можно указать заранее через `--ca-file`.

Мастер сохранит копию сертификата рядом с настройками. После этого исходный PEM
и переменные текущего терминала для запуска клиента не нужны.
TLS-проверка остаётся включённой. Сертификат с недоверенного сервера автоматически
не принимается; ошибка TLS не приводит к запросу ручного `x-api-key`.

Если задан `SSL_CERT_DIR`, мастер попросит убрать эту переменную на время настройки
и передать нужный доверенный PEM через `--ca-file`. Каталог сертификатов из окружения
не переносится в настройки клиента автоматически.

## Конфликты в OpenCode

Перед вводом ключей мастер покажет конфликтующие пути одним списком.
Отличие файла от пакета может быть и пользовательской правкой, и результатом старой установки.

| Выбор | Результат |
| --- | --- |
| `k` для скилла | Оставить свою версию и исключить её из будущих обновлений плагина |
| `r` | Сделать резервную копию и установить версию из поставки |
| Enter | Отменить настройку без замены файлов |

Для конфликта подключения `mcp.mlspace` доступна замена через `r` с резервной копией.
Мастер заменяет только это подключение; остальные MCP и комментарии JSONC сохраняются.
Дополнительные скиллы с отдельными именами не мешают установке.

Резервная копия скилла содержит весь его каталог, включая вспомогательные файлы.
Копии создаются после проверки ключей, перед заменой; точный путь печатается в терминале.
Если копию создать не удалось, оригиналы не заменяются.

`--force` не разрешает заменять конфликты автоматически. При `--non-interactive`
мастер перечисляет их и останавливается; для выбора запустите ту же команду в терминале
без этого флага. Проверка пропускает сверку с релизом для скиллов, оставленных через `k`.

В Claude Code/Codex конфликт имени каталога плагинов или отдельная старая регистрация
MCP также требуют разбора. Мастер сообщает путь и не удаляет другую интеграцию сам.

## Диагностические логи

`setup` и каждый запуск сервера создают отдельный журнал. По умолчанию это
`~/.config/mlspace-plugin/logs/`; точный путь мастер печатает в терминале.

- Ошибка установки: приложите соответствующий `setup-*.log`.
- Ошибка при работе с агентом: приложите свежий `server-*.log`.
- При наличии частей `.log.1` и `.log.2` приложите их вместе с основным файлом.

Журнал содержит версию плагина и Python, доступную версию клиента, этапы настройки,
маршруты API, HTTP-коды, длительность запросов и стек вызовов без значений переменных.
Ключи, пароли, заголовки, тела запросов и ответов, сырой вывод сторонних программ
и переписка с агентом в диагностический журнал не записываются.
Автоматической отправки журналов нет.

Права файлов — `0600`. Один файл ограничен 2 МиБ, сохраняются до двух предыдущих частей.
При новых запусках остаются последние 20 завершённых сессий; активные не затрагиваются.
Если создать журнал невозможно, выводится сообщение, а работа продолжается.

## Установка из локальной копии

В постоянном каталоге скачанного репозитория или распакованного ZIP выполните:

```sh
uv tool install --python ">=3.10" .
mlspace-plugin setup
```

Эта установка добавляет команду `mlspace-plugin`. Если она не найдена, следуйте
подсказке uv о каталоге исполняемых файлов в `PATH` и откройте новый терминал.
Для wheel вместо точки укажите путь к файлу `.whl`.

Для обновления перейдите в каталог **новой** копии и выполните:

```sh
uv tool install --python ">=3.10" --force .
mlspace-plugin setup --force
```

Не используйте временную editable-установку из `/tmp` для постоянного подключения.
Для Claude Code/Codex `setup` по-прежнему берёт нативный плагин из настроенного
GitHub-каталога; его версия должна совпадать с локальным установщиком.
Локальная копия сама по себе не делает установку полностью автономной от сети.

Git-тег в команде `uvx --from` фиксирует версию установщика и сервера OpenCode.
Claude Code/Codex устанавливают текущую версию из своего каталога плагинов.
Поэтому для обычной установки используйте актуальную команду из [INSTALL.md](INSTALL.md).

Для подготовки только файла настроек без проверки API есть специальное сочетание
`setup --config-only --no-verify --workspace UUID`. Результат отмечается как непроверенный;
клиенты и скиллы не подключаются. Это не способ исправления ошибки доступа.

## Ручное подключение и диагностика клиентов

После обычного `setup` следующие команды не нужны.
Они доступны при постоянной установке через `uv tool install`:

```sh
mlspace-plugin --list-tools
mlspace-plugin --transport stdio
```

Первый вызов показывает инструменты без ключей. Второй запускает MCP и ожидает
обмена с клиентом; это не интерактивный чат в терминале.
Для другого MCP-клиента можно указать команду `mlspace-plugin` и аргументы
`["--transport", "stdio"]`. При необходимости задайте в его окружении
`MLSPACE_ENV_FILE` с абсолютным путём к файлу настроек.

Для локального HTTP-подключения:

```sh
mlspace-plugin --transport streamable-http
```

Адрес — `http://127.0.0.1:8000/mcp`. Сервер не имеет встроенной аутентификации
HTTP-клиентов и отказывается слушать адреса вне loopback.

Проверка регистрации нативного плагина:

```sh
claude plugin marketplace list --json
claude plugin list --json
codex plugin marketplace list --json
codex plugin list --json
```

Каталог `mlspace` должен ссылаться на `https://github.com/cloud-ru/mlspace-plugin.git`,
а плагин `mlspace@mlspace` — быть включённым. Если команды `plugin` не поддерживаются,
обновите клиент. Если источник запрещён корпоративной политикой, согласуйте его
с администратором: повторные попытки установки запрет не снимают.

## Инструменты и воркспейсы

Сервер предоставляет 17 инструментов. Описание параметров и действий агент
получает через MCP; ниже — указатель по назначению.

| Инструмент | Для чего |
| --- | --- |
| `mlspace_contexts` | Выбранные воркспейсы и адрес API |
| `mlspace_jobs_overview` | Обзор задач в нескольких воркспейсах |
| `mlspace_notebooks_overview` | Обзор ноутбуков, включая приостановленные |
| `mlspace_queue_inspect` | Нагрузки и состояние очереди |
| `mlspace_jobs` | Запуск, состояние, логи и управление задачами |
| `mlspace_build_image` | Сборка контейнерных образов |
| `mlspace_notebooks` | Управление Jupyter-ноутбуками |
| `mlspace_tensorboards` | Управление TensorBoard |
| `mlspace_inference` | Сервисы инференса и запросы к модели |
| `mlspace_async_inference` | Асинхронный инференс |
| `mlspace_dalle` | Асинхронные запросы DALL-E |
| `mlspace_workspaces` | Сведения о воркспейсах и доступе |
| `mlspace_allocations` | Аллокации и типы ресурсов |
| `mlspace_queues` | Очереди и их узлы |
| `mlspace_docker_registry` | Репозитории, образы, теги и пароль Registry |
| `mlspace_data_transfer` | Коннекторы, правила переносов, история и логи |
| `mlspace_resources` | Каталог доступных вычислительных ресурсов |

Доменные инструменты принимают `action` и параметры выбранного действия.
Тело запроса передаётся в `body`. Локальная проверка выявляет явные структурные
ошибки; неизвестные значения и неоднозначные схемы проверяет сам API.
Строковые параметры допускают новые значения, даже если они ещё не перечислены
в подсказке инструмента.

### Выбор ресурса

`mlspace_contexts` показывает сохранённый набор без сетевого обхода.
У набора нет главного воркспейса. Для конкретного действия используется `target`
с ID или однозначным названием. Для найденной задачи или ноутбука сервер может
вернуть `resource_ref`: ссылку с окружением, воркспейсом и адресом объекта.
Противоречащие друг другу аргументы отклоняются.

Вопросы о конкретной задаче и её перезапуске сохраняют её адрес. Общий запрос
о задачах охватывает выбранный набор. Если место запуска неоднозначно, агент
должен уточнить его; образец ноутбука сам по себе не определяет воркспейс.
Просмотр доступных воркспейсов через `mlspace_workspaces` не расширяет выбранный набор.

### Полнота обзора

Обзорные инструменты ограничивают обход API: `page_size=100`, `max_pages=50`
на поток, `max_requests=200` на запросы инвентаря, `max_items=200` на вывод.
Авторизация, получение ключа и повтор после 401 — дополнительные обращения.
`targets` по умолчанию охватывает выбранные воркспейсы. Для узкого чтения задач
по региону используйте `mlspace_jobs` с `action=list` и пагинацией.

Смотрите `requested_scope`, `checked_scope`, `failures`, `observed_at` и `complete`.
`complete=true` означает полное успешное чтение без усечения результата.
`observed_count` при частичном чтении не является общим числом ресурсов.
Записи содержат `source`, `data`, `provenance` и, если адрес распознан, `resource_ref`.
Частичный поиск не доказывает уникальность имени; членство в воркспейсе не доказывает,
что все найденные задачи принадлежат этому пользователю.

Для переноса вычислительного узла сначала используйте `mlspace_queue_inspect`,
затем, если перенос запрошен, `mlspace_queues` с `action=add_nodes` и
`force_withdrawal:false`. Приостановленный ноутбук не означает занятую мощность,
а pending-задача — уже работающую нагрузку. `cross_workspace_coverage=unknown`
не позволяет обещать отсутствие влияния на чужие нагрузки общей аллокации.

### Встроенная спецификация

OpenAPI в поставке — снимок с выборочными обновлениями. Источник, дата и область
изменений записаны в `x-mlspace-snapshot-updates`; полнота текущего API не гарантируется.
Свежую схему предоставляет `/public/v2/openapi.json` выбранного API.
Примеры с `example.com` и `<YOUR_…>` требуют подстановки данных вашей задачи.
