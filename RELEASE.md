# Выпуск новой версии

Инструкция для сопровождающих проекта. Пользователю для обновления достаточно
[команды из INSTALL.md](INSTALL.md#обновление-и-повторная-настройка).

Сервер и скиллы выпускаются вместе через Git. Отдельной публикации нашего
Python-пакета в реестре нет; uv загружает только сторонние зависимости.

## 1. Обновите версию

Измените номер в `pyproject.toml` и `src/mlspace_mcp/__init__.py`, затем выполните:

```sh
uv lock
uv run python scripts/gen_plugin.py
```

## 2. Выполните проверки

Проверьте macOS и Linux:

```sh
uv sync --locked --extra dev
uv run --locked ruff check src scripts tests
uv run --locked mypy src
uv run --locked pytest
uv run --locked python scripts/gen_plugin.py --check
```

Проверки реальных клиентов могут пропускаться, если они не установлены.
Для приёмки проверьте Claude Code, Codex и OpenCode с изолированными
`HOME`, `XDG_CONFIG_HOME`, `CODEX_HOME` и `CLAUDE_CONFIG_DIR`.
Используйте тестовые ключи и локальный HTTPS API, а не ресурсы пользователей.

## 3. Соберите поставку

```sh
uv build
uv run python scripts/build_plugin.py
```

ZIP появится в `dist/plugins/`. В нём должны быть сервер, схемы API, скиллы,
манифесты, инструкции, лицензия и `SHA256SUMS`. Сборщик включает только разрешённые
файлы; `.env`, `.git`, кеши и виртуальные окружения в ZIP не входят.
Если каталог этой версии уже существует, выберите новый путь через `--output`.

Wheel и sdist используются для проверки сборки и локальной установки.
Загружать их в Python-реестр не требуется.

## 4. Проверьте архив отдельно от рабочей копии

Распакуйте ZIP и подставьте настоящий путь:

```sh
uvx --python ">=3.10" \
  --from '/путь/к/распакованному/плагину' \
  mlspace-plugin --list-tools
```

Затем проверьте установку, повторную настройку и обновление клиентов,
MCP initialize и доступность скиллов. Один `--list-tools` не подтверждает,
что клиент подключил сервер. Проверьте ссылки документации и наличие всех
упоминаемых локальных файлов в архиве.

## 5. Опубликуйте после согласования

Обновите Git-репозиторий и создайте тег `v<версия>` на том же коммите.
Приложите ZIP и его SHA256 к релизу. Для первой публичной поставки используйте
согласованный чистый снимок без старой истории и внутренних материалов.

Проверьте установку из опубликованного источника: версии установщика, сервера,
скиллов и манифестов должны совпадать. Для Claude Code/Codex проверьте также
актуальную версию в каталоге плагинов: Git-тег установщика сам по себе её не фиксирует.
При ошибке публикации или проверки не объявляйте релиз готовым.
