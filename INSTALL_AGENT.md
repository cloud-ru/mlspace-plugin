# Установка MLSpace: инструкция для агента

Используйте эту инструкцию, когда человек просит **установить или настроить** плагин.
Для обычной разработки проекта менять его клиентские настройки не требуется.
Поддерживаются macOS/Linux и три клиента: Claude Code, Codex, OpenCode.

## Основной сценарий

### 1. Выберите способ установки

Прочитайте [инструкцию для человека](INSTALL.md) из этой же версии плагина.
Проверьте доступность Git, uv и выбранного клиента.

| Исходная ситуация | Действие |
| --- | --- |
| Человек дал ссылку на репозиторий | Используйте Git-команду из INSTALL.md |
| Плагин уже установлен в Claude Code/Codex | Используйте его локальный каталог и `setup --config-only`, см. ниже |
| Есть постоянная локальная копия или wheel | Используйте [локальную установку](REFERENCE.md#установка-из-локальной-копии) |

Не оставляйте постоянное подключение к исходникам во временном каталоге `/tmp`.

### 2. Передайте ввод ключей человеку

Дайте одну готовую команду для **его терминала**, например:

```sh
uvx --python ">=3.10" \
  --from "git+https://github.com/cloud-ru/mlspace-plugin.git@main" \
  mlspace-plugin setup
```

Коротко объясните: выбрать клиент → ввести Key ID и Key Secret под звёздочками
→ найти и отметить воркспейсы → дождаться проверки.
На Linux по SSH команда выполняется на машине клиента.

Если известен нужный клиент, добавьте `--client claude-code`, `--client codex`
или `--client opencode`. Для stage добавьте согласованный `--base-url`.
Для повторной настройки используйте `--force`; для обновления — также `uvx --refresh`.

**Не просите ключи в чате.** Не читайте `.env`, не печатайте окружение,
не передавайте значения ключей в аргументах команды. Не открывайте для ввода
секретов терминал, доступный только вам. Дождитесь сообщения человека о завершении.

### 3. Проверьте результат в клиенте

Попросите открыть новую сессию клиента; при необходимости — перезапустить клиент.
Когда MCP появится, вызовите `mlspace_contexts` и сверьте выбранные воркспейсы.
Для проверки чтения можно запросить список задач без изменения ресурсов.

Различайте результаты:

- успешный `setup` подтверждает проверку скиллов и запуск отдельного процесса MCP;
- `--list-tools` показывает набор инструментов, но не доказывает подключение клиента;
- успешный вызов MCP в текущей сессии подтверждает, что эта сессия получила подключение.

Не заявляйте о проверке текущей сессии, пока вызов в ней не выполнен.

## Если нативный плагин уже установлен

Определите настоящий каталог установленного плагина по расположению его файлов.
В корне должны быть `pyproject.toml` и `src/mlspace_mcp/__main__.py`.
Прочитайте `INSTALL_AGENT.md` именно оттуда и дайте человеку команду:

```sh
uvx --python ">=3.10" \
  --from '/полный/путь/к/установленному/плагину' \
  mlspace-plugin setup --config-only
```

Подставьте реальный путь и корректно заключите его в кавычки.
`--config-only` настраивает доступ к MLSpace без повторной установки плагина.
Для запрошенной повторной настройки добавьте `--force`.
Каталог скиллов OpenCode не является каталогом сервера — этот способ к нему не относится.

## Если человек уже подготовил файл с ключами

Можно выполнить настройку без интерактивного ввода. Передавайте путь к файлу,
не открывая его содержимое. Следующие примеры используют вымышленные пути и ID.

**Найти воркспейсы:**

```sh
uvx --python ">=3.10" \
  --from "git+https://github.com/cloud-ru/mlspace-plugin.git@main" \
  mlspace-plugin setup --non-interactive \
  --credentials-file '/path/credentials.env' \
  --base-url https://api.ai.cloud.ru \
  --list-workspaces --search project --limit 20
```

Результат — JSON с `total`, `offset`, `limit`, `has_more` и метаданными воркспейсов.
Следующая страница: `--offset 20`. При неоднозначности уточните выбор у человека.

**Подключить выбранный воркспейс:**

```sh
uvx --python ">=3.10" \
  --from "git+https://github.com/cloud-ru/mlspace-plugin.git@main" \
  mlspace-plugin setup --non-interactive \
  --credentials-file '/path/credentials.env' \
  --base-url https://api.ai.cloud.ru \
  --client opencode --workspace WORKSPACE_UUID
```

Сохраняйте тот же адрес API, что использовался при поиске. Для нескольких клиентов
или воркспейсов повторяйте `--client` или `--workspace`. Если настройка уже есть,
добавьте `--force`. Сохранённые ключи на прежнем адресе можно переиспользовать
без `--credentials-file`.

Если ключи уже заданы в окружении вашего процесса, вместо файла можно использовать
`--from-env`. Не формируйте команды с литералами ключей: окружение другого терминала
не становится окружением агента автоматически.

## Что делать при ошибке

| Ошибка | Действие агента |
| --- | --- |
| Нет доступа к воркспейсу | Уточните выбор. В интерактивном режиме мастер вернёт человека к списку; в автоматическом повторите команду с согласованными ID |
| Конфликт OpenCode | Покажите пути и передайте выбор человеку: `k` оставляет его скилл, `r` делает резервную копию и заменяет, Enter отменяет |
| Конфликт в неинтерактивном режиме | Предложите ту же команду без `--non-interactive`, сохранив адрес API, пути и клиентов |
| Частично завершённая установка | Назовите завершённые этапы; используйте команду после «Повторите команду» из сообщения мастера |
| Ошибка TLS | Используйте системный доверенный CA или PEM от администратора через `--ca-file` |
| `blocked by enterprise policy` | Прекратите повторные попытки и направьте к администратору для согласования источника |

Не удаляйте пользовательские интеграции или каталоги скиллов ради устранения конфликта.
`--force` не разрешает замену пользовательских файлов. При автоматическом повторе
добавьте к напечатанной мастером команде прежние `--non-interactive` и `--workspace`.
Не исключайте недоступные воркспейсы молча и не обходите проверку через `--no-verify`.
Не отключайте TLS и не меняйте корпоративные политики.

Для диагностики используйте [журнал плагина](REFERENCE.md#диагностические-логи).
Не собирайте вместо него файл ключей, дамп окружения или сырой вывод клиента.
